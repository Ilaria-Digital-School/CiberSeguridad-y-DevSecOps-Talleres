# Filtra el tráfico de DNS UDP

**Recordatorio teórico** El protocolo DNS (Domain Name System) es el encargado de traducir nombres de dominio legibles por humanos (como www.ejemplo.com) en direcciones IP numéricas comprensibles por las máquinas. Por defecto, DNS utiliza el puerto 53 y funciona mayoritariamente sobre UDP, un protocolo sin conexión, sin handshake previo y sin confirmación de entrega. Esta elección se debe a la necesidad de rapidez: las consultas DNS son cortas (generalmente menos de 512 bytes) y la latencia importa más que la fiabilidad en la mayoría de los casos. TCP se reserva para DNS en situaciones específicas: transferencias de zona (AXFR) o respuestas que superan los 512 bytes. Un error frecuente entre los principiantes es confundir el tráfico DNS con cualquier tráfico UDP. DNS es un protocolo de capa de aplicación (capa 7 del modelo OSI) que utiliza UDP como transporte (capa 4). En Wireshark, un filtro incorrecto como 'udp' capturará todo el tráfico UDP, incluyendo DHCP, NTP y otros protocolos, lo que genera ruido innecesario. El filtro correcto para aislar únicamente tráfico DNS es 'dns' o, si se quiere ser más preciso, 'udp.port == 53'. Otro error habitual es olvidar que DNS también puede circular sobre TCP: un analista de seguridad debe tener esto presente al buscar anomalías. Modelo mental clave: DNS es el 'directorio telefónico' de internet. Cuando un navegador quiere contactar con un servidor, primero pregunta al resolvedor DNS '¿cuál es la IP de este dominio?'. Esta consulta y su respuesta son exactamente lo que vamos a capturar y filtrar...
