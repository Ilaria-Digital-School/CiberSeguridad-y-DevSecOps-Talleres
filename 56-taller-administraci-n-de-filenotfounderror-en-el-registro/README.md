# Taller: administración de FileNotFoundError en el registro

**Recordatorio teórico** En Python, cuando un programa intenta abrir un archivo que no existe en la ruta especificada, el intérprete lanza automáticamente una excepción de tipo FileNotFoundError. Esta excepción es una subclase de OSError y forma parte de la jerarquía de excepciones integradas de Python. Sin una gestión adecuada, este error provoca la interrupción inmediata del programa, lo cual es inaceptable en un contexto de automatización de seguridad donde los scripts deben ser robustos y fiables. El modelo mental a adoptar es el siguiente: todo acceso a un recurso externo (archivo, red, base de datos) es potencialmente fallido. Por ello, siempre se debe anticipar el fallo mediante un bloque try/except. La sintaxis básica es: try: f = open('archivo.log') except FileNotFoundError: print('Archivo no encontrado'). Un error frecuente de principiantes es capturar la excepción genérica Exception en lugar de FileNotFoundError, lo que oculta otros errores y dificulta el diagnóstico. Otro error común es olvidar cerrar el archivo en caso de éxito; para ello, se recomienda usar el gestor de contexto with open(...) as f. Mini-ejemplo: si intentas abrir 'sistema.log' y el archivo no existe, sin try/except el script se detiene; con try/except, puedes mostrar un mensaje claro, registrar el incidente y continuar la ejecución de forma controlada. --- **Enunciado del taller** En este taller vas a desarrollar un script Python que simula la lectura de un archivo de registro (log) de seguridad.
