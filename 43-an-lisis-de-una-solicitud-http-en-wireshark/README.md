# Análisis de una solicitud HTTP en Wireshark

**Recordatorio teórico** HTTP (HyperText Transfer Protocol) es el protocolo de la capa de aplicación (capa 7 del modelo OSI) que permite la comunicación entre un cliente (navegador, herramienta como curl) y un servidor web. Una solicitud HTTP está compuesta por un método (GET, POST, PUT, DELETE...), una URI, cabeceras (headers) y, opcionalmente, un cuerpo (body). La respuesta del servidor incluye un código de estado (200 OK, 404 Not Found, 302 Redirect...), cabeceras de respuesta y un cuerpo con el contenido. HTTP viaja sobre TCP (capa 4), lo que implica que antes de cualquier intercambio HTTP, existe un handshake TCP en tres pasos (SYN, SYN-ACK, ACK). Un error frecuente de los principiantes es confundir la trama Ethernet (capa 2), el paquete IP (capa 3), el segmento TCP (capa 4) y el mensaje HTTP (capa 7): en Wireshark, todos estos elementos están apilados dentro de un mismo paquete capturado. Otro error habitual es no aplicar filtros de visualización, lo que genera confusión ante el volumen de tráfico. Ejemplo mental: cuando escribes http://example.com en tu navegador, tu máquina resuelve primero el DNS, luego establece una conexión TCP con el servidor en el puerto 80, y finalmente envía una solicitud GET /.
