# Establecer un protocolo de enlace TCP a través de netcat

**Recordatorio teórico** El protocolo TCP (Transmission Control Protocol) opera en la capa 4 del modelo OSI (capa de transporte). A diferencia de UDP, TCP garantiza la entrega ordenada y fiable de los datos mediante un mecanismo de establecimiento de conexión conocido como 'three-way handshake' o protocolo de enlace de tres vías. Este proceso sigue tres pasos: (1) el cliente envía un segmento SYN al servidor indicando su deseo de conectarse y su número de secuencia inicial; (2) el servidor responde con un segmento SYN-ACK, reconociendo el SYN del cliente y comunicando su propio número de secuencia; (3) el cliente confirma con un ACK, completando así la conexión. Solo después de este intercambio los datos pueden fluir bidireccionalmente. Un error frecuente entre los principiantes es confundir el handshake TCP con el simple envío de datos: el handshake ocurre antes de cualquier transmisión útil. Otro error habitual es creer que netcat 'inventa' el protocolo: en realidad, netcat es simplemente una herramienta que expone el comportamiento nativo del stack TCP/IP del sistema operativo. Mini-ejemplo mental: imagina que llamas a alguien por teléfono. Primero suenas (SYN), la otra persona descuelga y dice 'Hola' (SYN-ACK), y tú respondes 'Hola' (ACK). Solo entonces comienza la conversación real.
