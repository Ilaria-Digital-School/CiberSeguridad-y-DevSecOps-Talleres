# Analice /var/log/auth.log en busca de detecciones

Recordatorio teórico: En un sistema Linux basado en Debian/Ubuntu, el archivo /var/log/auth.log centraliza todos los eventos relacionados con la autenticación y la autorización: intentos de conexión SSH (exitosos y fallidos), uso de sudo, cambios de sesión, creación de usuarios y actividad de PAM. En distribuciones basadas en Red Hat, el equivalente es /var/log/secure. Cada línea sigue un formato estándar syslog: marca de tiempo, nombre del host, proceso[PID] y mensaje. El modelo mental a adoptar es sencillo: un atacante que intenta comprometer un servidor deja rastros en este archivo. Un ataque de fuerza bruta SSH, por ejemplo, genera decenas o cientos de líneas 'Failed password for ...'. Una escalada de privilegios sospechosa aparece como líneas 'sudo: ... COMMAND=' o 'session opened for user root'. Los errores frecuentes de los principiantes son: leer el log línea por línea sin agregar ni contar (imposible detectar patrones), ignorar la correlación temporal entre eventos, y confundir 'Accepted password' (conexión exitosa) con 'Failed password' (intento fallido). Otro error clásico es olvidar que journald (visto en la actividad anterior sobre syslog/journald/logrotate) puede ser la fuente real en sistemas modernos, accesible con 'journalctl -u ssh'. Mini-ejemplo: la orden 'grep "Failed password" /var/log/auth.log | wc -l' cuenta rápidamente el número total de intentos fallidos. Combinada con 'awk' para extraer las direcciones IP, permite identificar en segundos qué dirección concentra la mayor cantidad de ataques.
