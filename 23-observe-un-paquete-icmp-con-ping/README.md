# Observe un paquete ICMP con ping

**Recordatorio teórico** Antes de comenzar, repasemos los conceptos esenciales que pondrás en práctica en este taller. Un paquete es la unidad fundamental de datos que viaja por una red: contiene una cabecera (con información de control como las direcciones IP de origen y destino) y una carga útil (los datos en sí). El protocolo ICMP (Internet Control Message Protocol) es un protocolo de la capa de red (capa 3 del modelo OSI) que permite a los dispositivos enviarse mensajes de control y diagnóstico. No transporta datos de aplicación: su propósito es informar sobre el estado de la red. El comando ping utiliza ICMP para enviar mensajes de tipo 'Echo Request' (tipo 8) a un host destino y esperar un 'Echo Reply' (tipo 0) en respuesta. Esto permite verificar la conectividad y medir el tiempo de respuesta (RTT, Round Trip Time). Error frecuente: muchos principiantes confunden ICMP con un protocolo de capa de transporte como TCP o UDP. ICMP no usa puertos; opera directamente sobre IP. Otro error habitual es interpretar el tiempo de respuesta del ping como el tiempo de ida solamente, cuando en realidad es el tiempo de ida y vuelta completo. Mini-ejemplo mental: imagina que envías una carta a un amigo y le pides que te responda de inmediato. El tiempo que transcurre desde que introduces la carta en el buzón hasta que recibes la respuesta en tu buzón es el RTT. El sobre es el paquete ICMP, y tu dirección y la del amigo son las direcciones...
