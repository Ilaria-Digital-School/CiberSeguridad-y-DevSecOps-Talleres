# Adaptación de los principios a un microservicio de carga de archivos

RECORDATORIO TEÓRICO La carga de archivos (file upload) es una de las funcionalidades más peligrosas de una aplicación web porque permite al usuario introducir datos arbitrarios en el servidor. Recuerda los pilares que ya has trabajado: la tríada CIA (Confidencialidad, Integridad, Disponibilidad) y los principios de diseño seguro, especialmente el mínimo privilegio (cada componente solo debe tener los permisos estrictamente necesarios) y la defensa en profundidad (varias capas de control independientes). A esto se suma STRIDE (Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege), tu modelo mental para enumerar amenazas sobre cada flujo de datos. Un microservicio de carga debe verse como un límite de confianza: todo lo que cruza desde el cliente es hostil hasta que se demuestre lo contrario. Errores frecuentes: validar el tipo de archivo solo por la extensión o por el Content-Type enviado por el cliente (ambos son falsificables), almacenar los archivos en la misma carpeta desde donde el servidor puede ejecutarlos, confiar en el nombre de archivo original (permite path traversal como ../../etc/passwd), o no limitar el tamaño (Denial of service). Mini-ejemplo: un usuario sube 'foto.jpg' que en realidad es 'shell.php'. Si el servicio solo comprueba la extensión visible y guarda el archivo en un directorio servido por el motor PHP, el atacante logra ejecución remota de código (Elevation of privilege + Tampering).
