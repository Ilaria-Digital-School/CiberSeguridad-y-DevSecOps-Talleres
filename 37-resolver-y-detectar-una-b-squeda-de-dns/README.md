# Resolver y detectar una búsqueda de DNS

**Recordatorio teórico** El DNS (Domain Name System) es el protocolo encargado de traducir nombres de dominio legibles por humanos (como www.ejemplo.com) en direcciones IP utilizables por las máquinas. Funciona de forma jerárquica: cuando un cliente realiza una consulta, primero verifica su caché local, luego consulta al resolver recursivo de su ISP o configurado manualmente, que a su vez interroga a los servidores raíz, los servidores de dominio de nivel superior (TLD) y finalmente el servidor autoritativo del dominio. Los tipos de registros más importantes son: A (IPv4), AAAA (IPv6), MX (correo), CNAME (alias), NS (servidor de nombres) y PTR (resolución inversa). El protocolo utiliza el puerto 53 UDP por defecto (y TCP para respuestas grandes o transferencias de zona). Errores frecuentes: confundir el resolver recursivo con el servidor autoritativo, olvidar que el TTL determina cuánto tiempo se guarda en caché una respuesta, o no considerar que el tráfico DNS puede ser interceptado o manipulado (DNS spoofing, DNS cache poisoning). Mini-ejemplo: al escribir 'ping google.com', el sistema operativo lanza una consulta DNS de tipo A hacia el resolver configurado; la respuesta contiene la IP destino que se usará para los paquetes ICMP.
