# Iniciar, detener o activar un servicio

RECORDATORIO TEÓRICO En los sistemas Linux modernos, systemd es el gestor de servicios y de arranque predominante. Un 'servicio' (o unidad de tipo .service) es un proceso gestionado por systemd: puede ser un servidor web (nginx, apache2), un servicio SSH (ssh/sshd), una base de datos, etc. El comando central para interactuar con estos servicios es 'systemctl'. Es fundamental distinguir dos conceptos que a menudo se confunden: el estado de ejecución (running/stopped) y el estado de activación al arranque (enabled/disabled). 'systemctl start servicio' inicia un servicio inmediatamente; 'systemctl stop servicio' lo detiene; 'systemctl restart servicio' lo reinicia; 'systemctl reload servicio' recarga la configuración sin cortar el servicio. Por otro lado, 'systemctl enable servicio' hace que el servicio se inicie automáticamente en cada arranque, mientras que 'systemctl disable servicio' lo impide. Un error muy frecuente es creer que 'enable' arranca el servicio de inmediato (no lo hace, salvo con la opción --now), o pensar que 'start' persiste tras reiniciar (no persiste sin 'enable'). Para verificar el estado, se usa 'systemctl status servicio', que muestra si está activo, su PID y las últimas líneas de registro. Los registros completos se consultan con 'journalctl -u servicio'. Mini-ejemplo: 'sudo systemctl enable --now ssh' activa el servicio SSH al arranque y lo inicia en el acto. 'systemctl is-enabled ssh' confirma la persistencia. En seguridad, controlar qué servicios están activos reduce la superficie de ataque: cada servicio en escucha es una puerta potencial.
