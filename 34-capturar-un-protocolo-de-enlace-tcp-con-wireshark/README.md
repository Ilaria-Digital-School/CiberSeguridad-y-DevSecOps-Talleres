# Capturar un protocolo de enlace TCP con Wireshark

RECORDATORIO TEÓRICO El protocolo de enlace TCP (TCP three-way handshake) es el mecanismo mediante el cual dos hosts establecen una conexión fiable antes de intercambiar datos. Consta de tres pasos fundamentales: SYN (el cliente solicita conexión enviando un segmento con el flag SYN activado), SYN-ACK (el servidor acepta y responde con los flags SYN y ACK simultáneamente), y ACK (el cliente confirma la recepción). Este proceso garantiza que ambos extremos estén listos para comunicarse y acuerden los números de secuencia iniciales (ISN). Modelo mental clave: piensa en el handshake como un apretón de manos formal: 'Quiero hablar contigo' → 'De acuerdo, yo también quiero hablar contigo' → 'Entendido, empezamos'. Cada paso tiene un número de secuencia que permite ordenar y reensamblar los paquetes. Errores frecuentes: confundir el flag ACK con un paquete de datos (el ACK del handshake no lleva payload), olvidar que los números de secuencia son relativos en la vista de Wireshark por defecto (Wireshark los normaliza a 0 para facilitar la lectura), e interpretar un RST como parte normal del handshake (indica un rechazo o cierre forzado). Mini-ejemplo: cuando tu navegador accede a http://example.com:80, primero se establece el handshake TCP en el puerto 80 antes de que se envíe cualquier byte HTTP. Sin ese handshake exitoso, no hay transferencia de datos. --- ENUNCIADO DEL TALLER Este taller te permitirá consolidar de forma práctica y autónoma los conocimientos adquiridos sobre TCP, el modelo OSI y el uso básico de Wireshark.
