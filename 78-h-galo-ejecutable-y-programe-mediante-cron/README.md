# Hágalo ejecutable y programe mediante cron

Recordatorio teórico: En Linux, un script no se ejecuta simplemente porque exista: el sistema debe reconocerlo como programa. Para ello intervienen dos elementos clave. Primero, el permiso de ejecución, que se otorga con el comando 'chmod +x archivo.sh'; sin este permiso el sistema devolverá un error de tipo 'Permission denied'. Segundo, la línea shebang '#!/bin/bash' al inicio del archivo, que indica qué intérprete debe procesar el script. Un modelo mental útil: el shebang dice 'con qué' ejecutar y el permiso dice 'si está permitido' ejecutar. Una vez que un script es ejecutable, cron permite automatizar su ejecución de forma periódica. Cron es un demonio que lee tablas llamadas crontab, donde cada línea sigue el formato: minuto, hora, día del mes, mes, día de la semana, seguido del comando. Por ejemplo, '30 2 * * * /home/user/backup.sh' ejecuta el script cada día a las 02:30. Errores frecuentes: olvidar el permiso de ejecución, usar rutas relativas en lugar de absolutas (cron no conoce tu directorio actual ni tu variable PATH completa), y no redirigir la salida para depurar. Mini-ejemplo completo: crear 'saludo.sh' con '#!/bin/bash' y 'echo "Hola $(date)" >> /tmp/log.txt', darle permiso con 'chmod +x saludo.sh' y programarlo con 'crontab -e' añadiendo '*/5 * * * * /ruta/absoluta/saludo.sh'. Así el saludo se registra cada cinco minutos. Dominar esta cadena (script → permiso → cron) es esencial en ciberseguridad para automatizar respaldos, auditorías y tareas de monitorización.
