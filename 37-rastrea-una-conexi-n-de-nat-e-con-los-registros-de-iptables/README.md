# Rastrea una conexión de Natée con los registros de iptables

RECORDATORIO TEÓRICO NAT (Network Address Translation) es un mecanismo que permite traducir las direcciones IP de los paquetes en tránsito, habitualmente en un router o firewall. En el contexto de iptables en Linux, NAT se gestiona principalmente en la tabla 'nat', con las cadenas PREROUTING (para modificar el destino de los paquetes entrantes, DNAT) y POSTROUTING (para modificar el origen de los paquetes salientes, MASQUERADE o SNAT). Cuando una conexión pasa por NAT, la dirección IP real del cliente queda oculta detrás de la IP del gateway, lo que complica el rastreo forense si no se dispone de logs adecuados. iptables permite registrar paquetes mediante el objetivo LOG antes de aplicar ACCEPT o DROP. Este mecanismo genera entradas en el syslog (generalmente /var/log/syslog o /var/log/kern.log) con información detallada: dirección IP origen, dirección IP destino, puerto origen, puerto destino, protocolo e interfaz de red. Un error frecuente de los principiantes es confundir el orden de evaluación de las cadenas: en NAT, PREROUTING se evalúa ANTES de que el kernel decida el enrutamiento, y POSTROUTING DESPUÉS. Si el LOG se coloca en el lugar incorrecto, no capturará la dirección original del cliente. Ejemplo mental: un cliente con IP 192.168.1.50 accede a un servidor web interno (10.0.0.5:80) a través de un gateway que aplica DNAT. Sin logs, en el servidor solo se ve la IP del gateway. Con LOG en PREROUTING antes del DNAT, se registra la IP real del cliente. Esta distinción es fundamental en ciberseguridad para la trazabilidad y el análisis...
