# Dibuja el DFD para la aplicación Blog

RECORDATORIO TEÓRICO Un Diagrama de Flujo de Datos (DFD) es una representación gráfica que muestra cómo circulan los datos dentro de una aplicación: quién los produce, por dónde pasan, dónde se almacenan y quién los consume. Es la base visual del modelado de amenazas porque expone claramente las superficies de ataque. El DFD utiliza cuatro símbolos fundamentales: las entidades externas (rectángulos o círculos externos) que representan actores fuera de nuestro control (usuario, atacante, servicio de terceros); los procesos (círculos o rectángulos redondeados) que transforman datos (ej. «Validar credenciales»); los almacenes de datos (dos líneas paralelas o un cilindro) como bases de datos y cachés; y los flujos de datos (flechas) que conectan los elementos e indican el sentido de circulación. El concepto más importante son los límites de confianza (trust boundaries), líneas punteadas que separan zonas con distintos niveles de privilegio: es precisamente donde un dato cruza un límite de confianza donde deben aplicarse controles de seguridad (autenticación, validación, cifrado). El modelo mental es simple: «sigue el dato». Empieza por el usuario y traza su recorrido hasta la base de datos y de vuelta. Errores frecuentes: olvidar los límites de confianza (el error más grave), confundir un proceso con un almacén de datos, dibujar flujos sin dirección, o mezclar niveles de detalle (un DFD de nivel 0 no debe contener detalles de nivel 2).
