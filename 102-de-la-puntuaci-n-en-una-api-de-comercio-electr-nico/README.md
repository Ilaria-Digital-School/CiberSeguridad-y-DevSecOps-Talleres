# de la puntuación en una API de comercio electrónico

RECORDATORIO TEÓRICO La puntuación de riesgos consiste en asignar un valor cuantificable a cada amenaza para poder priorizar las correcciones y las pruebas de seguridad. En los capítulos anteriores trabajaste con la metodología de calificación de riesgos de OWASP, que combina dos ejes: la PROBABILIDAD (likelihood) y el IMPACTO. La probabilidad se descompone en factores del agente de amenaza (habilidad, motivación, oportunidad, tamaño del grupo) y factores de la vulnerabilidad (facilidad de descubrimiento, de explotación, conocimiento público, detección de intrusiones). El impacto se divide en impacto técnico (pérdida de confidencialidad, integridad, disponibilidad, trazabilidad) e impacto de negocio (daño financiero, reputacional, cumplimiento, privacidad). El riesgo global se obtiene cruzando ambos ejes en una matriz (Bajo, Medio, Alto, Crítico). Modelo mental: 'Riesgo = Probabilidad × Impacto'. No confundas la gravedad técnica de una vulnerabilidad con su riesgo real: un fallo crítico expuesto solo en una red interna aislada puede tener un riesgo menor que un fallo medio expuesto en una API pública sin autenticación. Errores frecuentes: puntuar 'a ojo' sin justificar cada factor; olvidar el contexto de negocio; sobrevalorar amenazas mediáticas; e ignorar la trazabilidad. Mini-ejemplo: un endpoint /api/orders/{id} que devuelve pedidos ajenos (IDOR) tiene facilidad de explotación alta y pérdida de confidencialidad alta, por lo que su calificación tiende a Crítico. ENUNCIADO DEL WORKSHOP Se te entrega la descripción de una API REST de una plataforma de comercio electrónico ficticia llamada 'ShopFast'. Esta API expone, entre otros, los siguientes endpoints: autenticación con token JWT (/api/auth/login), consulta de perfil de usuario (/api/users/{id}),...
