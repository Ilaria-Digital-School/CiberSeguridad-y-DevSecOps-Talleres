# Proteger una carpeta compartida

RECORDATORIO TEÓRICO En Linux, cada archivo y carpeta pertenece a un usuario (owner) y a un grupo (group), y define tres conjuntos de permisos: propietario, grupo y otros (world). Los permisos básicos son lectura (r=4), escritura (w=2) y ejecución (x=1). Sobre un directorio, el permiso 'x' es indispensable para acceder a su contenido (hacer cd o atravesarlo), 'r' permite listar los nombres de archivos y 'w' permite crear o eliminar entradas dentro de la carpeta. Para gestionar el acceso colectivo se usan grupos: con 'chown' se cambia el propietario, con 'chgrp' el grupo, y con 'chmod' los permisos (simbólico como u+rwx,g+rx,o-rwx o digital como 770). Existe además un bit especial fundamental para carpetas compartidas: el SGID (chmod g+s o 2xxx sobre un directorio) fuerza a que los archivos creados dentro hereden el grupo de la carpeta, garantizando colaboración coherente. Otro bit clave es el sticky bit (chmod +t o 1xxx), que en carpetas comunes impide que un usuario borre archivos que no le pertenecen, aunque tenga permiso de escritura en el directorio (el ejemplo clásico es /tmp). Errores frecuentes: dar 777 'para que funcione' (grave fallo de seguridad), olvidar el bit 'x' en carpetas, o confundir permisos del directorio con permisos de los archivos. Mini-ejemplo: una carpeta /srv/equipo con grupo 'dev', permisos 2770 y sticky bit permite que solo miembros de 'dev' trabajen juntos sin exponer datos a otros usuarios.
