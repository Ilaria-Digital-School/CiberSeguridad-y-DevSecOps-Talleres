# Reconstruir la cronología de un incidente conocido

Recordatorio teórico Reconstruir la cronología de un incidente de seguridad significa organizar los eventos detectados en el orden temporal correcto, desde la preparación inicial del ataque hasta la remediación final. Este proceso, fundamental en la investigación forense digital, transforma datos dispersos en una narrativa comprensible que revela el método, la motivación y el impacto del atacante. Un modelo mental útil considera el ciclo de vida de un incidente. Este ciclo suele dividirse en fases como la preparación, el compromiso inicial, la propagación lateral, la acción sobre los objetivos y la limpieza o persistencia. Para cada evento identificado, usted debe preguntarse: ¿esta acción pertenece al despliegue inicial, a la movilidad interna o al momento del impacto? Este enfoque estructura el análisis. Un error frecuente es confundir la primera detección con el momento real del compromiso. Los atacantes pueden permanecer ocultos durante meses antes de ser descubiertos. Otro error es ignorar los eventos preparatorios, como el reconocimiento de la red o la compra de dominios maliciosos, que son parte integral de la línea de tiempo. Un miniejemplo: en un ataque de phishing típico, la cronología comienza días antes con el registro de un dominio falso (Día 1), sigue con el envío masivo de correos (Día 3), el primer clic de una víctima (Día 3, +2 horas), la ejecución del malware (Día 3, +5 minutos) y la exfiltración de datos (Día 4).
