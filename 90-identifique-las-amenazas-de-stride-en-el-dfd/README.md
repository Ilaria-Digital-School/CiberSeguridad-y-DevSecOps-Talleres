# Identifique las amenazas de STRIDE en el DFD

Recordatorio teórico: El modelado de amenazas consiste en anticipar cómo un atacante podría comprometer una aplicación antes de que sea explotada en producción. El método STRIDE, creado por Microsoft, clasifica las amenazas en seis categorías: Spoofing (suplantación de identidad), Tampering (manipulación de datos), Repudiation (repudio de acciones), Information Disclosure (divulgación de información), Denial of Service (denegación de servicio) y Elevation of Privilege (elevación de privilegios). El Diagrama de Flujo de Datos (DFD) es la representación visual sobre la que se aplica STRIDE: usa entidades externas (rectángulos), procesos (círculos), almacenes de datos (líneas paralelas) y flujos de datos (flechas). La clave del método es que cada tipo de elemento del DFD es vulnerable a categorías STRIDE específicas: las entidades externas sufren Spoofing y Repudiation; los flujos de datos sufren Tampering, Information Disclosure y Denial of Service; los procesos son vulnerables a las seis; los almacenes de datos a Tampering, Information Disclosure, Repudiation y Denial of Service. Un error frecuente es aplicar STRIDE de forma genérica sin anclarlo a un elemento concreto del diagrama, o confundir amenaza (lo que puede pasar) con vulnerabilidad (el defecto que lo permite). Mini-ejemplo: en el flujo «navegador → API de login» un atacante podría interceptar credenciales en tránsito (Information Disclosure) si no hay TLS, o modificar la petición (Tampering) para saltarse validaciones. Prestar atención especialmente a los límites de confianza (trust boundaries), donde las amenazas se concentran.
