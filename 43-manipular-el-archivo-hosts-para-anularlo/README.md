# Manipular el archivo hosts para anularlo

**Recordatorio teórico** El archivo hosts es uno de los mecanismos de resolución de nombres más antiguos de los sistemas operativos. Antes de que existiera el DNS, era el único método para traducir nombres de dominio en direcciones IP. Hoy en día, sigue activo en todos los sistemas modernos (Linux, Windows, macOS) y se consulta **antes** que el servidor DNS configurado en el sistema. Esta prioridad es fundamental: si una entrada existe en el archivo hosts, el sistema la utiliza directamente sin realizar ninguna consulta DNS externa. En Linux y macOS, el archivo se encuentra en `/etc/hosts`. En Windows, en `C:\Windows\System32\drivers\etc\hosts`. Su sintaxis es sencilla: cada línea contiene una dirección IP seguida de uno o varios nombres de dominio separados por espacios o tabulaciones. Ejemplo: `127.0.0.1 miservidor.local`. Desde el punto de vista de la ciberseguridad, este mecanismo tiene implicaciones críticas. Un atacante con acceso al sistema puede modificar este archivo para redirigir el tráfico destinado a un dominio legítimo (por ejemplo, un servicio bancario o un servidor de actualizaciones) hacia una IP controlada por él. Esta técnica se denomina **envenenamiento del archivo hosts** o **host-based DNS spoofing**. También es utilizada legítimamente por pentesters para redirigir peticiones hacia entornos de prueba, o por administradores para bloquear dominios maliciosos apuntando a `0.0.0.0` o `127.0.0.1`. Error frecuente: confundir la caché DNS del sistema con el archivo hosts. Aunque ambos afectan la resolución de nombres, son mecanismos distintos.
