# de STRIDE en un punto final de API para «crear publicación»

RECORDATORIO TEÓRICO STRIDE es un método de modelado de amenazas creado por Microsoft que ayuda a identificar sistemáticamente los riesgos de seguridad de un sistema. Su nombre es un acrónimo de seis categorías de amenazas: Spoofing (suplantación de identidad), Tampering (manipulación de datos), Repudiation (repudio), Information Disclosure (divulgación de información), Denial of Service (denegación de servicio) y Elevation of Privilege (elevación de privilegios). Cada categoría se opone a una propiedad de seguridad deseable: la suplantación amenaza la autenticación, la manipulación amenaza la integridad, el repudio amenaza la no repudiación, la divulgación amenaza la confidencialidad, la denegación amenaza la disponibilidad y la elevación amenaza la autorización. Encontrarás aquí un puente directo con la tríada CIA (confidencialidad, integridad, disponibilidad) que ya estudiaste. El modelo mental consiste en recorrer cada flujo de datos, cada entrada y cada límite de confianza del sistema, y preguntarse metódicamente: ¿puede alguien suplantar aquí? ¿alterar los datos? ¿negar una acción? Etcétera. Un error frecuente entre principiantes es confundir la amenaza (lo que podría pasar) con la vulnerabilidad (el defecto que lo permite) o con el control (la medida que lo mitiga). Otro error es querer analizar toda la aplicación de golpe: STRIDE se aplica mejor componente por componente o flujo por flujo. Mini-ejemplo: en un endpoint de inicio de sesión, la amenaza «Spoofing» sería que un atacante use credenciales robadas para hacerse pasar por otro usuario; el control asociado podría ser MFA o límites de intentos.
