# Asocie los escenarios de riesgo con los 10 principales de OWASP (mapas)

RECORDATORIO TEÓRICO El OWASP Top 10 es una lista de referencia que clasifica las diez categorías de riesgos de seguridad más críticas para las aplicaciones web. Cada categoría (por ejemplo A01: Broken Access Control, A03: Injection, A07: Identification and Authentication Failures) agrupa familias de vulnerabilidades con causas y consecuencias comunes. El modelo mental útil aquí es sencillo: un escenario de riesgo describe cómo un actor amenaza (attacker) explota una vulnerabilidad sobre un activo, provocando un impacto en la Confidencialidad, la Integridad o la Disponibilidad (CIA). Tu tarea consiste en «mapear» ese escenario hacia la categoría OWASP correcta. Ejemplo: «Un usuario modifica el parámetro id=123 en la URL y accede a la factura de otro cliente». El activo es la factura, la vulnerabilidad es la falta de control de acceso a nivel de objeto, el impacto principal es la Confidencialidad. Este escenario se asocia a A01: Broken Access Control (IDOR). Errores frecuentes: confundir A01 (Control de acceso) con A07 (Autenticación) —autenticarse es probar quién eres, autorizar es lo que puedes hacer—; clasificar toda inyección como XSS cuando A03 cubre SQL, NoSQL, comandos, etc.; olvidar que un mismo escenario puede tocar varias categorías, en cuyo caso debes justificar la categoría dominante. Mantén el reflejo activo→amenaza→vulnerabilidad→impacto para no equivocarte.
