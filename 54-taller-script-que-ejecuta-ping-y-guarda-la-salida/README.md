# Taller: script que ejecuta 'ping' y guarda la salida

**Recordatorio teórico** En el capítulo anterior exploraste la biblioteca `subprocess` de Python, que permite lanzar comandos del sistema operativo directamente desde un script. El módulo `subprocess` expone principalmente dos interfaces: `subprocess.run()` para ejecuciones simples y bloqueantes, y `subprocess.Popen()` para un control más fino de los procesos. El parámetro `capture_output=True` (o alternativamente `stdout=subprocess.PIPE`) redirige la salida estándar del proceso hacia tu script, lo que te permite leerla como una cadena de bytes. Para obtener texto legible, deberás decodificar esa cadena con `.decode('utf-8')` o usar el parámetro `text=True`. Un error frecuente en este contexto es olvidar manejar la excepción `FileNotFoundError`, que se lanza cuando el ejecutable indicado no existe en el sistema (por ejemplo, si el comando `ping` no está disponible en la ruta). Otro error habitual es ignorar el código de retorno del proceso (`returncode`), lo que impide detectar fallos silenciosos. El comando `ping` varía entre sistemas: en Linux/macOS se usa `ping -c 4 `, mientras que en Windows es `ping -n 4 `. Antes de escribir cualquier código, verifica el comportamiento de tu sistema. Mini-ejemplo: `resultado = subprocess.run(['ping', '-c', '2', '8.8.8.8'], capture_output=True, text=True)` almacena la salida en `resultado.stdout`. --- **Enunciado del taller** En este taller construirás un script Python funcional que automatiza la ejecución del comando `ping` contra uno o varios hosts, captura la salida producida por el sistema operativo y la guarda de forma estructurada en un archivo de texto en disco.
