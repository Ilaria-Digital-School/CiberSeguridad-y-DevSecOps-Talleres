# Mapea la superficie de ataque del blog

RECORDATORIO TEÓRICO La superficie de ataque de una aplicación es el conjunto de todos los puntos por los que un atacante podría intentar entrar, extraer datos o alterar el sistema. Se compone de tres dimensiones principales: la superficie de red (puertos, protocolos, servicios expuestos), la superficie de aplicación (endpoints HTTP, formularios, parámetros, APIs, cabeceras, cookies, ficheros subidos) y la superficie humana/de datos (cuentas, roles, secretos, dependencias de terceros). El modelo mental correcto es simple: «cada entrada de datos no confiable y cada componente accesible es una puerta potencial». Cuanto más grande sea la superficie, mayor será el riesgo y más pruebas habrá que priorizar. Un error frecuente entre principiantes es limitar la superficie a lo visible en el navegador y olvidar los endpoints internos (panel de administración, API REST, healthchecks), los servicios de soporte (base de datos, caché, colas) o las dependencias externas (CDN, pasarelas de pago, autenticación con terceros). Otro error es confundir «superficie de ataque» con «vulnerabilidad»: mapear la superficie no consiste en encontrar fallos, sino en inventariar los puntos de entrada antes de probar. Mini-ejemplo: en un blog, la página pública de artículos es un punto de entrada (GET /post/:id → posible IDOR o inyección en el parámetro id). El formulario de comentarios es otro (POST → XSS almacenado, CSRF). El login de administración es un tercero (fuerza bruta, bypass de autenticación).
