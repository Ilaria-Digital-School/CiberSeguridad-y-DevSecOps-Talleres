# Taller reforzado: aplicación de las mejores prácticas a hello.py

RECORDATORIO TEÓRICO Las mejores prácticas de scripting seguro en Python no son simples convenciones estéticas: son la primera línea de defensa contra errores de seguridad introducidos en la fase de desarrollo. En ciberseguridad y DevSecOps, un script mal escrito puede exponer credenciales, ejecutar código con privilegios excesivos o producir salidas no controladas que faciliten ataques posteriores. Conceptos clave a recordar: (1) Gestión de secretos: jamás se almacenan contraseñas, tokens o claves API directamente en el código fuente. Se utilizan variables de entorno (os.environ) o archivos de configuración excluidos del control de versiones (.gitignore). (2) Derechos mínimos: un script debe ejecutarse con el nivel de privilegios estrictamente necesario. (3) Logging seguro: los mensajes de log no deben revelar información sensible. (4) Manejo de errores: las excepciones deben capturarse y gestionarse sin exponer trazas internas al usuario final. (5) Validación de entradas: cualquier parámetro externo debe ser validado antes de ser utilizado. Error frecuente: incluir credenciales hardcodeadas en el script 'por comodidad durante las pruebas' y olvidar eliminarlas antes de subir el código a un repositorio. Este error es la causa de miles de fugas de datos anuales detectadas en repositorios públicos como GitHub.
