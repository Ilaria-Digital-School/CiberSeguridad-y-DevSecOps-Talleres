# Señales y muerte en la práctica

RECORDATORIO TEÓRICO En Linux, una señal es un mensaje asíncrono que el kernel envía a un proceso para notificarle un evento o pedirle que reaccione. Cada señal tiene un número y un nombre simbólico. Las más importantes para este taller son: SIGTERM (15), que pide educadamente a un proceso que termine y le permite limpiar sus recursos; SIGKILL (9), que fuerza la terminación inmediata y no puede ser ignorada ni capturada; SIGHUP (1), usada a menudo para recargar la configuración de un demonio; SIGSTOP y SIGCONT, que suspenden y reanudan un proceso; y SIGINT (2), la señal generada por Ctrl+C. El comando principal es 'kill', complementado por 'killall' y 'pkill' para actuar por nombre o patrón. El modelo mental correcto es: primero se intenta un cierre limpio (SIGTERM) y solo si el proceso no responde se recurre a la fuerza bruta (SIGKILL). Un proceso puede definir manejadores (handlers) para capturar ciertas señales y ejecutar código antes de morir; por eso SIGKILL es especial: no es capturable. Errores frecuentes: usar 'kill -9' de entrada por costumbre (impide la limpieza y puede corromper datos); confundir el PID con el número de señal; olvidar que un proceso zombie no muere con kill porque ya está muerto (espera a su padre); y matar el proceso equivocado con 'pkill' por un patrón demasiado amplio. Mini-ejemplo: 'kill -TERM 1234' pide a PID 1234 que termine; si sigue vivo, 'kill -9 1234' lo elimina de forma forzada. 'kill -l' lista todas las señales disponibles. ENUNCIADO DEL WORKSHOP...
