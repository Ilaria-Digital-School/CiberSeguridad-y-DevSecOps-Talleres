# Localice los activos en una aplicación de «Lista de tareas pendientes»

RECORDATORIO TEÓRICO Antes de defender una aplicación, hay que saber qué se protege. Un activo (asset) es todo elemento que tiene valor para la organización o para el usuario y cuya pérdida, robo o alteración causaría un perjuicio. En una aplicación existen varias categorías de activos: los datos (credenciales, información personal, contenido de los usuarios), las funciones sensibles (autenticación, gestión de cuentas, pagos), los componentes técnicos (base de datos, servidor, API, tokens de sesión, claves) y la reputación o disponibilidad del servicio. Modelo mental útil: pregúntate «¿qué querría robar, modificar o destruir un atacante, y por qué?». Cada activo se caracteriza por su valor según tres criterios clásicos (CIA): Confidencialidad, Integridad y Disponibilidad. Recuerda las definiciones vistas anteriormente: una amenaza es un evento potencial que atenta contra un activo; una vulnerabilidad es una debilidad que la amenaza puede explotar; y el riesgo combina la probabilidad de explotación con el impacto sobre el activo. No hay riesgo sin activo: por eso la identificación de activos es el primer paso del modelado de amenazas. Errores frecuentes: confundir un activo (lo que se protege) con una vulnerabilidad (una debilidad); olvidar los activos «invisibles» como los tokens de sesión, las variables de entorno o las copias de seguridad; y limitarse a los datos ignorando las funciones críticas. Mini-ejemplo: en un blog, un activo evidente es «la base de datos de usuarios» (confidencialidad e integridad altas), mientras que «la página de inicio pública» tiene baja confidencialidad pero requiere disponibilidad.
